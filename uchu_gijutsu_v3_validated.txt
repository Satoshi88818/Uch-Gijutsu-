Findings made during validation Things the tests exposed that I did not anticipate, kept here because they change how results should be read: 1. **The DType throughput table was inverted** in v2 (defect #8 above) — not in the original review. 2. **Sparse speedup is below the nominal 1.85× in practice** (1.76× on an 8192³ GEMM) because pipeline fill/drain cycles do not shrink with sparsity. My first test assumed ≈1.85 and was wrong; the model was right. Speedup approaches 1.85× only for deep reductions (K = 131072 → 1.85 ± 1 %). 3. **FP16/INT8 throughput ratio is 1.94×, not 2×**, for the same reason. 4. **M = 1 GEMV is compute-limited, not memory-bound**, on an output-stationary 256² array (utilisation < 1 %: 255 of 256 PE rows idle). It becomes memory-bound only if HBM bandwidth is scarce. This is a property of the assumed dataflow, not a bug; a weight-stationary or batched mapping would change it. 5. **Fill/drain is charged to every tile by default** (`pipeline_overlap = 0.0`, conservative). Real arrays overlap drain of tile *i* with fill of tile *i+1*; for shallow-K layers (attention, K = 64) this can make v3 up to several × pessimistic. Set `compute.pipeline_overlap` from your microarchitecture. 6. **A mistake of mine, caught by a test:** I initially described a flare as a ~6000× upset-rate enhancement. The correct figure at a mid-inclination LEO orbit is ≈ 6× (trapped protons dominate the baseline there); at GEO, where the baseline is tiny, it exceeds 10³×. I had compared a per-day rate with a per-second rate. The tests now assert both regimes. 7. **A placeholder error, caught by an ordering test:** the GEO trapped-proton factor was 0.01, which made GEO proton upsets ~70× larger than its GCR rate. GEO has no significant trapped protons; it is now 0. 8. **The flare test initially failed to count enough events** because my "hot" cross-section inflation was too mild; inflation factors are now sized so each statistical assertion has ≥10³ events. --- ## 5. """ from __future__ import annotations import zlib import numpy as np def _spawn_key(keys) -> tuple:     return tuple(zlib.crc32(str(k).encode("utf-8")) for k in keys) def make_rng(seed: int, *keys) -> np.random.Generator:     """Independent Generator for (seed, *keys)."""     ss = np.random.SeedSequence(entropy=int(seed), spawn_key=_spawn_key(keys))     return np.random.default_rng(ss) def child_seed(seed: int, *keys) -> int:     """Integer seed derived from (seed, *keys);
